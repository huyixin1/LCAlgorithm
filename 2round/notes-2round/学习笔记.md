## 2026-09-09（Day 2 开始前复习 Day 1 所得）

**核心结论：什么时候用哈希，什么时候用排序+双指针？**

- **需要返回所有不重复的组合** → 排序 + 双指针（先排序去重，双指针找组合）
- **只需要返回一组解 / 判断是否存在** → 哈希表（O(n)，更快）

**原因**：
- 哈希表虽然 O(n)，但"去重"很麻烦：不知道哪些组合已经出现过，容易输出重复结果
- 排序 + 双指针是 O(n log n)（排序）+ O(n)（双指针），但排序天然让重复元素相邻，去重只需跳过相邻相同值，干净利落

**例子对比**：
- 15 三数之和：要**所有**不重复组合 → 排序 + 双指针
- 1 两数之和：只要**一组**解 → 哈希表

> 判断口诀：见到"所有不重复组合"→ 排序 + 双指针；见到"是否存在 / 一组即可"→ 哈希。

## 2026-09-09（Day 2 链表学习所得）

**1. 链表操作的本质：只有指针，没有"新链表"**
- 合并/拼接链表 = 改变节点的 next 指向，**节点本身不复制、不新建**
- 21 合并：唯一新建的节点是 dummy（占位），tail 只是游标。空间 O(1)
- 理解锚点：链表不是"对象集合"，是"next 指针的链条"。操作链表就是操作指针

**2. None vs ListNode()（206 的坑）**
- `None` = 链表的结束标志
- `ListNode()` = 一个实实在在的节点（val=0, next=None）
- 初始化 pre 用 None，用 ListNode() 会凭空多出一个假节点

**3. 虚拟头节点 dummy 的两大作用**
- 统一边界：头节点删除时不用特判，最后 `return dummy.next` 永远正确（19）
- 提供起点：合并/重排时 tail 从 dummy 开始串（21）

**4. 快慢指针边界条件（234 的坑）**
- 找中点：`while fast and fast.next`，两个条件都要，否则 None.next 报错

**5. 142 环入口结论（今天自己复述对了，加深记忆）**
- slow 走 1 步、fast 走 2 步，有环必在环内相遇
- 相遇后：**一个指针放回链表头**，另一个留在相遇点，两指针同速走
- 再次相遇的位置 = 环入口。记结论即可，证明以后再看

## 2026-09-10（Day 3 单调栈专题）

**1. 单调栈是统一套路，不是每道题一个技巧**

题目怎么"翻译"成单调栈（识别信号，按出现频率）：
- **"右边第一个更大/更小"** → 单调栈（739 每日温度、496 下一个更大元素）
- **"左边第一个更大/更小"** → 单调栈（84 柱状图：找左右第一根更矮的）
- 套路特征：数组 + 每个元素都要"向左/右看"找第一个边界
- 一句话翻译模板：
  - 找**下一个更大** → 维护**递减**栈（栈顶最小），新元素比栈顶大时弹出，**新元素就是栈顶的答案**
  - 找**下一个更小** → 维护**递增**栈

**2. 统一框架（背这个）**
```python
for x in nums:
    while stack 非空 and 栈顶 与 x 破坏单调性:
        弹出栈顶 → x 就是它的答案 → 结算/记录
    入栈 x
```
- 关键认知：**弹出的那一刻 = 答案出现的那一刻**。每个元素入栈一次、出栈一次 → O(n)

**3. 84 柱状图（为什么用单调递增栈）**
- 每根柱子最大矩形 = 高度 × (右边界 − 左边界 − 1)
- 右边界 = 右边第一根更矮的柱子；左边界 = 左边第一根更矮的柱子
- 用递增栈：遇到更矮的 h，栈顶的右边界确定了（就是 h），左边界是栈里它下面那根 → 弹出结算
- 结尾补高度 0 的柱子，强制所有元素出栈结算

**4. Python 小知识点（错题里暴露的，都要记住）**
- `is` 比较内存地址，`==` 比较值。判断相等永远用 `==`
- 空栈 `stk.pop()` 会抛 `IndexError` → 先 `if not stk` 判空
- 列表最后一个元素：`stk[-1]`（-1 索引）
- `not stk` = 栈为空

**5. 复杂度速成（欠账补上）**
- 数循环层数：一层循环 O(n)，两层嵌套 O(n²)
- 但单调栈虽然是 for + while，每个元素最多进出栈一次，总操作 O(n) → 不是 O(n²)
- 判断口诀：**看每个元素被访问几次**。被常数次访问 → O(n)；每个元素都要扫一遍剩余 → O(n²)

**1. 画调用树 + 返回值树（重要方法 ✅）**
- 每道递归题先在纸上画出：递归调用的展开过程（调用树）+ 每层向上返回什么（返回值树）

**2. 543 的核心认知：一个递归只能返回一个东西 ⭐**
- 直径 = 左高 + 右高，但**高度**和**直径**是两个不同返回值
- 解法：辅助函数返回高度（给父节点用），全局变量记录直径（每个节点处结算一次）
- 一句话：**高度向上传递，直径就地结算**
- 延伸：只要"既要子树信息给父节点、又要记录全局最优"的题，都是这个模式（后续的 DP 树形题同款）

**3. 101 对称判断**

- 想明白：对称 = 我的左子树 对应 你的右子树

**4. 114 展开为链表：先保存引用再动手**
- 操作节点时，凡是"要改指针但后面还要用原引用"的场景，先把 left/right 存进变量
- 检查边界：左子树为空时跳过拼接

**5. 二叉树递归四步框架（用户自己总结）**

## 2026-09-12（Day 5 二叉树进阶：两个重要认知）

**1. 验证 BST 的两种方法（都要会）**
- 方法 A：中序遍历 + prev 比较（严格递增）
- 方法 B：**传区间上下界**。递归携带 (lower, upper)，当前节点值必须在区间内；往左走 upper 收紧为当前值，往右走 lower 收紧为当前值。用 None 表示 ±∞
- 为什么不能只比较直接孩子：BST 要求整棵左子树 < 根 < 整棵右子树，跨层约束只比较孩子会漏（[5,1,6,null,null,3,7] 反例）

**2. 递归返回值传递：返回值链不能断 ⭐**
- 辅助函数递归到子树里找到答案后，**每一层都必须把子调用的返回值 `return` 上去**
- 常见 bug：`inorder(node.left)` 递归找到了，但这层没 return，答案在返回途中丢失（230 题）
- 自查：凡是有返回值语义的递归，检查每条递归路径是否都有 return

**3. 对节点操作 vs 对子树操作（通用判断口诀）⭐**
> **问自己：我需不需要先知道左右子树的结果，才能决定当前节点？**
> - 需要 → **后序**：先递归子树，拿到返回值，再处理当前节点（236 LCA、543 直径、104 深度）
> - 不需要 → **前序**：先处理当前节点，再递归（226 翻转、打印遍历）

- LCA 的函数语义："返回这棵子树里找到的目标"——左右都找到 → 当前是答案；只有一边 → 传上去；自己就是目标 → 返回自己
- 这个口诀覆盖所有二叉树题，做题前先问一遍

## 2026-09-14（周日回顾复习所得）

**1. 543 空间复杂度：递归空间 = 调用栈深度，不是变量个数 ⭐**
- 错误理解：每遍历一个节点初始化两个变量 → O(n)
- 正确：局部变量存在各自的**栈帧**里，同时存在的栈帧数 = **递归深度 = 树高**。最坏 O(n)（链状树退化），平衡树 O(logn)
- 记忆：看递归"最多同时挂多深"，不是看总共调用多少次

**2. 15 三数之和去重三件套（9/14 暴露的盲点）**
1. 外层固定 i：`if i > 0 and nums[i] == nums[i-1]: continue`
2. 找到一组后：`l += 1; r -= 1` **两边同时动**
3. 内层跳过重复：`while l < r and nums[l] == nums[l-1]: l += 1`、`while l < r and nums[r] == nums[r+1]: r -= 1`
- "右侧有两个以上符合条件"不是问题：双指针逐个找出全部组合，去重只是避免结果重复

**3. 114 反复出错的边界：左子树为空**
- 找左子树链尾前先判断 `if not node.left: 直接接右子树`
- 已经第二次在这栽了 → 写递归前先列边界：空节点 / 单边为空 / 正常

**4. 236 延伸：LCA II（p/q 可能不在树里）**
- 236 原题保证 p、q 都在树里
- 变体解法：加两个全局标志 found_p / found_q，遍历时置位；后序逻辑不变；最后检查两个标志都 True 才返回结果，否则 None

## 2026-09-15（Day 6 回溯：断层接上）

**1. 回溯三大识别信号**
- "所有组合 / 全排列 / 所有可能" → 回溯
- 选择之间有依赖（用过的不能再选、不能回头）→ 回溯
- 要枚举所有可能性 → 回溯

**2. 组合 vs 排列：start 和 used 的区别 ⭐**
- **组合/子集**（78/39）：顺序无关 → 用 `start` 只能往后选，防止回头
- **排列**（46）：顺序有关 → 用 `used[]` 标记，每层从头选但不能重复选
- 记法：组合是"往后的路"，排列是"没走过的路"

**3. 回溯优化两招（39 自己悟的 ⭐）**
1. **把 path 的和/状态作为参数传递**（O(1) 维护，不要每次 sum(path) 重算）
2. **排序 + 越界剪枝**：`if nums[i] > remain: break`（排序后更大的更不可能）

**4. 22 括号生成的本质**
- 本质 = "(" ")" 各 n 个的全排列里找**合法排列**
- 合法性两条规则：① 不能先出现右括号（右括号数 < 左括号数才可加）② 左括号数 < n 才可加左
- 剪枝在选择时做，不是在终止时做

**5. 236 延伸：为什么 p/q 不在树里也能终止（面试题）**
- 用户疑问："p/q 不在树里那不就无法终止吗？"
- **关键澄清：递归终止条件和 p/q 是否在树里无关**！递归靠"空节点返回"终止，会走完整棵树，自然结束
- 236 原题 p/q 保证在树里 → 返回值里一定有非 None 答案
- 变体（p/q 可能不在）：返回逻辑不变，但**只找到一个时无法区分"是 LCA"还是"只找到一个"** → 加 found_p/found_q 标志，最后都 True 才返回答案
- 一句话：**遍历会自然终止；标志位负责"验证答案合法性"**

**6. 回溯框架（背这个）**
```python
def dfs(路径, 选择列表):
    if 满足结束条件: 记录结果; return
    for 选择 in 选择列表:
        做选择
        dfs(路径, 新选择列表)
        撤销选择
```
- 递归进去 = 前序做选择；递归返回 = 后序撤销选择（N 叉树的后序遍历）

## 2026-09-16（Day 7 动态规划入门）

**1. 509 和 70 是同一种题（用户自己悟出 ⭐）**
- 斐波那契：`f(n) = f(n-1) + f(n-2)`。爬楼梯就是斐波那契（到 n 阶 = 从 n-1 跳 + 从 n-2 跳）
- **抽象能力**：能看出两道题同构 = 真正理解了 DP 的"状态"

**2. 198 打家劫舍（用户独立推导 ✅）**
- 状态：dp[i] = 前 i 家最多偷多少
- 转移：`dp[i] = max(dp[i-1], dp[i-2] + nums[i])`——第 i 家偷/不偷二选一
- 和斐波那契同源：都是"从上一个状态推当前状态"，只是变成取 max

**3. 322 为什么不能贪心（重点 ⭐）**
- 直觉："先拿最大的硬币"（贪心）
- 反例：coins=[1,3,4], amount=6 → 贪心 4+1+1 = 3 枚；最优 3+3 = 2 枚
- **贪心和 DP 的分界线**：贪心每步做"局部最优选择"，但硬币组合的全局最优**不一定包含最大面额**；DP 枚举所有可能取最优
- 记忆：**要"枚举所有可能"→ DP；要"每步做最优选择"→ 贪心**

**4. 322 正确框架 + 边界模板**
```python
def coinChange(coins, amount):
    dp = [float('inf')] * (amount + 1)
    dp[0] = 0
    for a in range(1, amount + 1):
        for c in coins:
            if a - c >= 0:
                dp[a] = min(dp[a], dp[a-c] + 1)
    return dp[amount] if dp[amount] != float('inf') else -1
```
- 初始化：`dp[0] = 0`（金额 0 用 0 枚）
- 不可达 = inf，返回时判断

**5. 78/46 复习确认**
- 78 子集：没写 start → 死循环；start 的作用 = **只能往后选**（防重复 + 防回头死循环）
- 46 全排列：used 数组 = **每层从头选但不能重复选**
